2026-09-27 - Decision: the Win32 `MEMORYSTATUSEX` structure is declared with fixed-width `c_uint32`/`c_uint64` rather than `c_ulong`. `c_ulong` is 4 bytes on Windows but 8 on 64-bit Linux, so a `c_ulong` declaration would be silently wrong on every host except the one that actually calls it, and no test run anywhere else would catch it. The fixed-width form is the documented 64-byte layout on every platform, which is what lets a test assert the layout while running on macOS or Linux. The upstream body is never read into a string anywhere in the handler; handing `upstream.body` straight to the `Response` is what makes it stream, and re-introducing a buffering read would reintroduce the original defect.

2026-09-28 - Decision: on resume, the in-memory task and the reloaded case use different strategies. When the client still holds the task, the stream resumes from the cursor via `Last-Event-Id`, leaving rendered steps untouched. When the state is gone, the log is replayed from id 0 instead of seeding from `loadTask`, because `loadTask` maps steps from the aggregate `plan` and `tool_calls` columns under different step ids than replayed events use; replaying on top of it would append a second copy of every plan and tool step. Artifact manifests are the one thing replay cannot rebuild, since `artifact_created` carries only `artifact_id` and `artifact_type` (G9), so they are merged from the snapshot afterwards.
